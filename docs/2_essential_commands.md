# Essential Commands

## 1. Container Execution & Interaction
The core commands used to deploy, enter, and interact with running application containers.

* **`run`**: Creates and starts a container in a single command. The most heavily used Docker command.
    * **Common Flags**: `-d` (detached/background), `-p` (port mapping), `-v` (volume mount), `-e` (environment variables), `--name` (assign name).
    * *Example:* `docker run -d -p 8080:80 --name my-web nginx`
* **`exec`**: Runs a new command inside an already running container (crucial for troubleshooting).
    * **Common Flags**: `-i` (interactive), `-t` (allocate a pseudo-TTY).
    * *Example:* `docker exec -it my-web bash` (Opens a bash shell inside the container).
* **`attach`**: Attaches your local terminal's standard input/output streams to a running container's main process.
* **`cp`**: Copies files or directories between a container and the local host filesystem.
    * *Example:* `docker cp ./local.txt my-web:/app/local.txt`
* **`commit`**: Freezes a container's current state and writable layer, saving it as a brand new Image.
    * *Example:* `docker commit my-web customized_nginx:v1`

## 2. Container Lifecycle Management
Commands to manage the state of containers without interacting with their internal processes.

* **`create`**: Creates a container but does not start it (uses the same flags as `run`).
* **`start`**: Starts one or more stopped containers.
* **`stop`**: Gracefully stops a running container by sending a SIGTERM signal.
* **`restart`**: Stops and then immediately restarts a container.
* **`pause`**: Suspends all processes within a container (freezes it in RAM).
* **`unpause`**: Resumes a paused container.
* **`rename`**: Changes the assigned name of an existing container.
    * *Example:* `docker rename my-web old-web`
* **`update`**: Dynamically updates resource configurations (like CPU/RAM limits) of a running container without stopping it.
    * *Example:* `docker update --memory "512m" my-web`
* **`wait`**: Blocks the terminal until a container stops, then prints its exit code.
* **`rm`**: Deletes a stopped container.
    * **Common Flags**: `-f` (force delete a running container), `-v` (remove associated anonymous volumes).
    * *Example:* `docker rm -f my-web`

## 3. Image Management & Build Operations
Commands for creating, downloading, and manipulating Docker images.

* **`build`**: Builds a Docker Image from a `Dockerfile`.
    * **Common Flags**: `-t` (tag/name the image), `-f` (specify Dockerfile path).
    * *Example:* `docker build -t myapp:1.0 .`
* **`bake`**: An advanced build command used with Docker Buildx to execute high-level builds defined in HCL, JSON, or Compose files.
* **`pull`**: Downloads an image from a remote registry (like Docker Hub) to your local machine.
    * *Example:* `docker pull ubuntu:22.04`
* **`images`**: Lists all locally stored Docker images.
    * **Common Flags**: `-a` (show all, including intermediate hidden layers), `-q` (show only Image IDs).
* **`tag`**: Assigns a new label or alias to an existing image (required before pushing to a custom registry).
    * *Example:* `docker tag myapp username/myapp:v1`
* **`push`**: Uploads a locally built image to a remote registry.
    * *Example:* `docker push username/myapp:v1`
* **`history`**: Displays the step-by-step layer history of an image, showing how it was built and the size of each layer.
* **`rmi`**: Removes one or more local images.
    * *Example:* `docker rmi -f myapp:1.0` (Forces removal even if containers are using it).

## 4. Monitoring & Troubleshooting
Essential commands for DevOps and System Administrators to analyze system health and logs.

* **`ps`**: Lists containers.
    * **Common Flags**: `-a` (lists all containers, including stopped ones), `-q` (lists only container IDs).
    * *Example:* `docker ps -a`
* **`logs`**: Fetches the internal application logs generated by a container.
    * **Common Flags**: `-f` (follow logs live), `--tail 50` (show only the last 50 lines).
    * *Example:* `docker logs -f my-web`
* **`inspect`**: Returns detailed low-level JSON data about a container, image, or network (e.g., IP addresses, mount paths).
    * *Example:* `docker inspect my-web`
* **`stats`**: Displays a live-streaming dashboard of container resource usage statistics (CPU, RAM, Network I/O).
* **`events`**: Streams real-time operational events from the Docker daemon (e.g., when containers are created, stopped, or die).
* **`diff`**: Inspects all changes made to files or directories on a container's internal filesystem compared to its base image.
* **`port`**: Lists the current public-to-private port mappings for a specific container.

## 5. Registry & Authentication
* **`login`**: Authenticates your Docker client with a remote registry (Docker Hub by default).
    * *Example:* `docker login -u myusername`
* **`logout`**: Logs out of a Docker registry, removing stored credentials.
* **`search`**: Searches Docker Hub directly from the terminal for public images.
    * *Example:* `docker search nginx`

## 6. Import, Export & Save (Data Portability)
Commands for manually transferring containers or images without a registry.

* **`save`**: Saves an Image to a `.tar` archive file (preserves all layers and history).
    * *Example:* `docker save -o myimage.tar ubuntu:latest`
* **`load`**: Loads an Image from a `.tar` archive file created by `save`.
* **`export`**: Exports a Container's current filesystem to a `.tar` archive (flattens all layers, loses history).
    * *Example:* `docker export -o mycontainer_fs.tar my-web`
* **`import`**: Creates a completely empty, flat Image by importing the contents of a tarball created by `export`.

## 7. System Info
* **`info`**: Displays system-wide Docker information (total containers, storage driver, kernel version, available RAM).
* **`version`**: Shows the installed Docker Engine and Client version details.
* **`help`**: Displays the manual and flag options for Docker or a specific command.
    * *Example:* `docker run --help`
